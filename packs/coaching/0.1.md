# Coaching schema pack 0.1

Declared in a vault as `packs = ["coaching@0.1"]`. Compiled into the
`confidant` binary in v0 (ADR-8). This file is the pack contract.

Coaching types are not core. A vault without this pack has people, orgs,
deals, interactions, notes, aliases, merges, stages, and generic balance
assertions only.

## Verbs

### `open`

```
DATE open PERSON-ID package PKG-ID N sessions
```

Opens (or renews) a package of `N` sessions for a person. `PKG-ID` uses the
`pkg-` prefix. Multiple `open` lines accumulate. `N` is a positive integer
capped at 100000. An invalid `PKG-ID` is `E_INVALID_ID`. Overflow of `N` or
of the running open total is `E_OPEN_MALFORMED`.

Malformed `open` lines are `E_OPEN_MALFORMED`.

### `session`

```
DATE session PERSON-ID DURATION [paid|pps|comp] [note:NOTE-ID] [src:PROVENANCE]
```

`DURATION` is `Nm`, `Nh`, or `NhNm` (for example `60m`, `1h`, `1h30m`).
Minutes are integers. Billing tags:

- `paid` consumes a package slot.
- `pps` (pay-per-session) never consumes.
- `comp` (complimentary, chemistry, or pro bono) never consumes.

A session with none of these tags still consumes, because that is the safe
choice for balances. It also gets `W_SESSION_UNTAGGED`, which asks for
`paid`, `pps`, or `comp`. A session with more than one of these tags is
`E_SESSION_TAGS`. A plain `paid` session **can** drive `E_NEGATIVE_BALANCE`
when the person has no remaining package.

`note:NOTE-ID` links a note that belongs to the session's person (after merge
canonicalization). An invalid note ID is `E_INVALID_ID`; a missing note or a
note for another person is a finding. These `note:` integrity checks always
run, independent of `coaching.session_notes` and `--as-of`. `src:` records
provenance (`src:transcript/t-…`, `src:portal/evt-…`) and is the
content-level dedupe key for later imports (ADR-8). Duplicate `src:` values
are `E_DUPLICATE_SRC`.

`open` and `session` require a person ID (`E_WRONG_ID_TYPE` otherwise). A
merge between different record types (for example `merge p-X into o-Y`) is
also `E_WRONG_ID_TYPE` and is not applied.

A session without a parseable duration is `E_MISSING_DURATION` (default:
error; key `coaching.require_duration`).

## Metrics

A merge takes effect from its own date. When evaluating a metric as of date
`D`, apply only merges dated on or before `D`. Later merges never change
earlier assertions. Current-state views and gap rules evaluated at `as_of`
apply merges dated on or before `as_of`. Once the evaluation date is on or
after the merge date, FROM's whole history, including events before the
merge, counts toward the canonical ID.

| Metric | Formula |
|---|---|
| `sessions_remaining` | sum(`N` from `open` on or before the as-of date) − count(consuming `session`s on or before that date) |
| `icf_hours` | sum(session durations dated on or before the as-of date, in minutes) / 60, compared at 2 decimal places |

A `balance PERSON-ID sessions_remaining N` or `balance PERSON-ID icf_hours X`
line is an assertion against these metrics **as of the end of the assertion
date** (`E_BALANCE_MISMATCH` on disagreement). Entries dated later, including
later merges, never affect it.

If `sessions_remaining` is negative, `E_NEGATIVE_BALANCE` fires (default:
error; key `coaching.balance_nonnegative`).

## Gap rules (architecture section 9b)

Capture going stale is a first-class failure mode: Confidant only knows what
was written. These rules flag gaps so an agent can send a weekly summary.

### `E_SESSION_WITHOUT_NOTES`

A `session` line has notes when any of the following is true:

1. It carries `note:NOTE-ID`, that note exists, and it belongs to the
   session's (canonical) person.
2. A note record for the same person has `date` or `session` equal to the
   session date.
3. A note file lives at `people/PERSON-ID/notes/` and its front matter `date`
   or `session` equals the session date.

The coverage warning considers only sessions dated on or before `--as-of` /
`[checks].as_of`. `note:` integrity (invalid ID, wrong type, missing record,
wrong owner) is always on.

Otherwise `E_SESSION_WITHOUT_NOTES` fires. Default severity: warning. Key:
`coaching.session_notes`.

Two sessions on the same day share same-day notes: if a same-day note exists,
both sessions are considered covered. Prefer `note:` when two sessions need
distinct notes.

### `E_PAID_SESSION_GAP`

A person is a **paid client** when computed `sessions_remaining > 0` as of
`as_of`, **or** they have a `pps` session on or after
`as_of - coaching.pps_lookback_days` (inclusive) and on or before `as_of`.
The lookback defaults to 180 days, is validated like the gap days, and is
capped at 3650.

For each paid client, if there is no `session` on or after `as_of - days`
(inclusive) and on or before `as_of`, `E_PAID_SESSION_GAP` fires. `days`
comes from `coaching.paid_session_gap_days` (default 45, cap 3650). `as_of`
comes from `--as-of`, else `[checks].as_of`, else today's UTC date.

The gap clock runs from `max(last session, latest open)`, so a returning
client who opens a new package is not flagged until `days` days have passed
with no session. A client with remaining sessions who never had a session
is a gap only when that `open` is more than `days` days before `as_of`. A
package client whose remaining balance is 0 and who has no `pps` session in
the lookback is not paid for this rule. A `pps` client whose last session
is inside the lookback but outside the gap window **is** flagged.

Default severity: warning. Key: `coaching.paid_session_gap`. Set the key to
`off` to disable.

Boundary: a last session exactly `days` ago is inside the window. A last
session `days + 1` ago is a gap.

## Find / privacy

This pack does not change core `find` rules. Spec 0.1 sections 12–13 apply:
`find` returns content only from the cleared allowlist.

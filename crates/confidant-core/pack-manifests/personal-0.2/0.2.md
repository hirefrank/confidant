# Personal schema pack 0.2

Declared in a vault as `packs = ["personal@0.2"]`. Compiled into the
`confidant` binary as a built-in **declarative** pack (#550): its bytes ship
inside the binary and are loaded through the same manifest-v2 / declarative
path external packs use (ADR-8). A vault may list it alongside `coaching@0.1`;
each pack owns its own verbs, fields, edge kinds, and check rules, and folds
the ledger independently (#177). `personal@0.1` stays available as the
compiled pack (PD14) until the cutover (#551).

The machine-readable source of the pack's claims is
[`manifest.toml`](manifest.toml) (spec `spec/pack-manifest.md`). Because the
bytes are loaded from **compiled-in** origin, the pack is trusted as core
(#504 decision 3): its rules name the stable finding codes directly and it may
claim the core `touch` verb. The allowance is keyed on the bytes' origin,
never the pack name, so a vault directory `packs/personal@…` still fails
`E_PACK_INVALID` (#504 R8).

`personal@0.2` supersedes `personal@0.1` (#504). Breaking changes from 0.1:
`relationship_to_me` is renamed to `relationship`; `cadence` accepts `never`;
`birthday`/`dates`/`cadence`/`relationship` are re-expressed declaratively;
and the touch-kind list drops `coffee` (use `meal`). New fields: `title`,
`company`, `location`, `emails`, `phones`, `links`, `tags`, `snooze_until`.

## Fields

This pack owns optional flat front-matter fields on any `person` record
(spec §8); the same key on a non-person record is unattributed and ignored. A
value that does not match its grammar is `E_FRONTMATTER`.

| Field | Grammar | Meaning |
|---|---|---|
| `title` | non-empty string | Job title. |
| `company` | non-empty string | Employer. |
| `location` | non-empty string | Free text; not geocoded. |
| `emails` | list | Contact emails. No syntax validation or normalization. |
| `phones` | list | Contact phone numbers. No parsing or normalization. |
| `links` | labeled list | `LABEL:VALUE` profiles (for example `linkedin:https://…`). |
| `tags` | list | Free-form labels; `/` expresses hierarchy. |
| `birthday` | `YYYY-MM-DD` or `--MM-DD` | Date of birth. |
| `dates` | comma-separated `LABEL:DATE` | Other recurring dates. |
| `relationship` | non-empty string | How the person relates to the operator. |
| `cadence` | `<N>d` or `never` | Keep-in-touch interval; `N` is `1..=3650`. |
| `snooze_until` | `YYYY-MM-DD` | One-off snooze date for the cadence nudge. |

Lists are comma-separated, optionally wrapped in one `[...]`; entries are
trimmed, non-empty, and unique. A labeled-list splits at the first `:`,
`LABEL` matches `[a-zA-Z0-9_-]+`, and the value is trimmed, non-empty and may
contain `:`.

`cadence: never` is a valid value meaning the person is never overdue: the
cadence rule skips them (no warning, not even the "no contact" variant).

`snooze_until` suppresses `W_CADENCE_OVERDUE` while `as_of < snooze_until`
(the person is eligible again on the snooze date; a past date has no effect).
Only the canonical person's own record is read.

## Edge kinds

Core ships `married`, `introduced`, and `colleague`; `personal@0.2` adds the
same kinds as 0.1: symmetric `friend`, `family`, `sibling`, `partner`, and
directed `parent` (`a` is the parent of `b`) and `mentor`. A symmetric kind
must not appear twice for the same unordered pair (`E_DUPLICATE_EDGE`); a kind
no core or enabled pack claims is `E_UNKNOWN_EDGE_KIND`.

## Verbs

### `touch`

```
DATE touch PERSON-ID call|text|email|meet|meal|event|gift|other [note:NOTE-ID] [src:PROVENANCE]
```

Records a touchpoint: called, texted, emailed, met, had a meal with, attended
an event with, gave a gift to, or other. The kind is a closed list; a kind
outside it, a missing kind, a misplaced argument or a duplicate `kind:` pair
is `E_TOUCH_MALFORMED` (a core code). The core mirrored shape is accepted too:

```
DATE touch PERSON-ID [kind:KIND]
```

`note:NOTE-ID` links a note that belongs to the touched person (after merge
canonicalization): an invalid note ID is `E_INVALID_ID`; a `note:` that is not
a note record is `E_WRONG_ID_TYPE`; a missing note, or one belonging to
another person, is `E_UNKNOWN_RECORD`. `src:PROVENANCE` records provenance;
duplicate `src:` values are `E_DUPLICATE_SRC` (core).

## Rules

Both rules are warning-level nudges: they surface what to do next and never
block a write, a commit, or an inbox merge (#183). Each is configurable
through `[checks]`.

### `W_CADENCE_OVERDUE`

Default severity `warning`; key `personal.cadence_overdue`
(`"warning" | "error" | "off"`).

Fires for a person with `cadence: <N>d` who has no touchpoint on or after
`as_of - N` days (inclusive) and on or before `as_of`. A touchpoint is a
`touch` ledger line or a coaching `session` ledger line for that person,
after merge canonicalization. `cadence: never` and an active `snooze_until`
skip the person. `as_of` comes from `--as-of`, else `[checks].as_of`, else
today's UTC date.

### `W_DATE_UPCOMING`

Default severity `warning`; key `personal.date_upcoming`
(`"warning" | "error" | "off"`); window `personal.date_upcoming_days`
(default `7`, cap `3650`).

Fires when a person's `birthday` or an entry in `dates` has its next
occurrence within `0..=personal.date_upcoming_days` days of `as_of`. A
year-less `--MM-DD` value is the next `MM-DD` on or after `as_of`.

## Privacy and scoping

The pack honours `no-ai` on person records (`true`, `false`, or `notes`): a
`no-ai: true` person is excluded from `find`, `context`, and agent output,
while a `no-ai: notes` person stays visible but their notes and interactions
default to hidden (spec §13). PII fields (`location`, `emails`, `phones`,
`links`, `tags`, `birthday`, `dates`, `relationship`) are stripped from
`context --exclude-private`; `cadence` and touch metadata stay. Per-pack
scoping (#178) applies: `--packs personal@0.2` limits agent reads to core and
personal-owned items.

Use fake data (`Ada Example`, `Bea Demo`, fake ULIDs) in tests, fixtures, and
examples. Never commit real contact details.
